# 佣金计算器架构备注

> 当前有效业务规则以 `docs/business-rules.md` 为准。本文件记录的是当前代码结构的职责边界和后续整理约定，不是业务规则本身。

## 当前职责边界

### `src/commission/calculator.py`

- 只负责佣金计算。
- 不做 GUI 交互。
- 不做飞书 API 请求。
- 不做文本格式化。
- 不读取 `.env`。

### `src/commission/formatter.py`

- 只负责把计算结果格式化成 CLI/GUI 统一文本。
- 不做输入处理。
- 不做网络请求。
- 不做业务计算。

### `src/commission/records.py`

- 只负责把计算结果转换成可写入的 `CommissionRecord`。
- 不做飞书 API 请求。
- 不做 GUI/CLI 交互。

### `src/commission/feishu.py`

- 只负责飞书多维表格的认证、建表、查表、写记录。
- 不负责从计算结果抽取记录。
- 不负责 `.env` 的全局副作用加载。

### `src/commission/config.py`

- 只保留业务常量：房源类型、角色比例、支付费率、平台费率、提成比例。
- 不做文件 IO。
- 不做 `.env` 读取。

### `src/commission/settings.py` 或 `src/commission/env.py`

- 只负责运行配置读取。
- 负责飞书凭证等环境变量或 `.env` 加载。
- 不承载业务比例常量。

### `src/commission/cli.py`

- 只负责命令行交互。
- 不重复维护文本格式化逻辑。
- 不负责飞书记录抽取。

### `src/commission/gui/`

- 只负责桌面交互和页面状态管理。
- 不重复维护文本格式化逻辑。
- 不直接包含飞书记录转换逻辑。

## 当前已知耦合点

1. CLI 和 GUI 各有一套结果格式化逻辑，后续要合并到统一 formatter。
2. `feishu.py` 当前同时承担记录抽取和 API 写入，后续要拆成 `records.py + feishu.py`。
3. `config.py` 当前同时包含业务常量和 `.env` 加载，后续要把运行配置移出。
4. `calc_agent_shares()` 同时兼容成交人/房源方拆分，后续可以考虑拆成两个入口，但这不是第一优先级。

## 重构顺序约定

1. 先统一展示文本。
2. 再拆记录转换。
3. 再清理配置副作用。
4. 最后整理复杂计算函数。

## 不动项

以下内容在当前阶段不动：

- GUI 布局重做
- 业务比例重新定义
- 规则可配置化
- 历史记录/数据库持久化
- 飞书表结构扩展
- 打包流程重写

## 验证原则

每次结构调整后都要先跑现有测试，再继续下一步。优先保证：

- 计算结果不变
- 平台实勘仍被正确标记
- 多业务员拆分仍闭合
- 飞书写入仍可用
